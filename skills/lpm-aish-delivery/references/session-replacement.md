# Audited delivery session replacement
Load when: the owner explicitly approves replacing a failed session with an equivalent completed successor.

This is not retry, release approval or activity closure. It creates no jobs and changes no budgets. Never infer approval from a successful successor. Use {{skill:lpm-governance-decisions}} to record the owner's exact decision first.

1. Read {{tool:get_issue}} and {{tool:get_aish_execution_session}} for both sessions. Obtain projectId/issueId, sourceSessionId/successorSessionId and their current approved plan hashes from these responses, never from guesses. The same issue must retain both session IDs.
2. Require the owner's own explicit order in this conversation and a resolved clarification thread naming both sessions. Missing either → STOP and request the owner decision. Caller must be the workspace owner using their existing authorized credential; never create or broaden credentials.
3. Call {{tool:replace_aish_delivery_session}} with projectId, issueId, both session IDs and approved hashes, decisionThreadId, the approved reason, and dryRun=true. No idempotencyKey parameter exists. Errors → STOP: preserve history and report the exact unmet condition. Do not create another job, delete sessions or weaken criteria.
4. Require dryRun=true, a fingerprint, complete nodeMapping and zero failures. Plans must keep all obligations, scope, dependencies, agent bindings, financial/runner limits, validation commands and selected files equivalent; only a bounded builder's textual instruction can differ. Source must be terminal failed/canceled, successor completed and independently passing its own technical DoD. This does not constitute independent human review.
5. With the same approved inputs, call {{tool:replace_aish_delivery_session}} with dryRun=false and expectedFingerprint from step 3. Concurrent changes → re-read and repeat the dry-run; no guessed fingerprint. Keep replacement.id, actor, hashes, mapping and decision reference. Timeout → repeat dryRun=true with the identical inputs; reused=true returns the existing immutable receipt, not proof of current acceptance.
6. Verify using {{tool:audit_aish_issue_delivery}}: replacements includes that exact record and both sessions, historicalStatus remains failed/canceled. Re-read both sessions and {{tool:get_issue}}: neither history nor sessionIds was erased. A blocked audit is still blocked; never claim completion. Evidence corruption, changed approval or a reopened/changed decision invalidates acceptance. Attach the receipt/audit through {{skill:lpm-deliver-activity}}.

Report: owner quote and decision thread, replacement receipt, audit status, historical failure preserved, no new jobs/budget, remaining requirements. A technical DoD pass does not waive business acceptance, independent review or post-cutover stability requirements.
